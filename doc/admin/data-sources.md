# Mails sent by a site: data sources

A quote form, a shop or an application sends its notifications from its own address: Settings > Data sources (admins
of Dolibarr) says which senders to trust (addresses or domains, a domain covers its subdomains) and which headers
name the real requester. Format advised for a module that sends such mails:

```
X-Data-Form-Email: jean.dupont@example.com
X-Data-Form: {"firstname":"Jean","lastname":"Dupont","company":"Dupont SARL","phone":"+33 1 23 45 67 89","siren":"123456789","vat":"FR12123456789","id":"D-1042"}
```

JSON on one line, 2000 characters at most, RFC 2047 when it holds accents, each header once. Usual key names are
understood (`email`, `firstname`, `lastname`, `company`, `phone`, `siren`, `vat`, `address`, `zip`, `town`, `id`),
others are mapped on the source; one header per field is possible too (`X-Form-Phone = phone`).

The headers are believed only for a trusted sender that is authenticated (DMARC, or DKIM of its domain, read on the
`Authentication-Results` of the receiving servers of Settings > Server). Then the thirdparty is looked for on the
address of the requester, the list shows him with the badge of the source, the creation pages are filled with his
data and « Reply » writes to him. Nothing is written in Dolibarr by the headers alone. The source given at the
installation (`X-Quotation-Mail`, `X-Quotation-Data`) is disabled and has no trusted sender.

## Signed sources (1.143.0)

Some mail servers write no `Authentication-Results`, and a site often sends through the mail server of the mailbox
itself, without DKIM: the rule above then refuses every mail of the site. A source can be given a **signing key**
shared with its site (field « Signing key » of the source: pasted, or generated by the browser and copied into the
site). The key is stored encrypted and never shown again. The site adds a third header:

```
X-Data-Form-Signature: t=1795620187; s=<64 hexadecimal digits>
```

`t` is the time of the signature (Unix time), `s` the HMAC-SHA256 in hexadecimal, with the key, of `t`, a line
break, the value of the address header, a line break and the value of the data header (empty when the source has no
such header). The name of the header can be changed on the source.

- A mail of a trusted sender with a right signature is believed without the authentication of its sender.
- A wrong signature, or one more than 2 days away from the `Date` of the mail, is refused: the authentication is never
  tried instead. Without the signature header, the rule of the unsigned sources applies.
- The signature covers the address and the data headers only: the headers « one per field » are not read on a signed
  mail.

In PHP, for example where the site builds its notification:

```php
$email = 'jean.dupont@example.com';
$data = json_encode(array('firstname' => 'Jean', 'lastname' => 'Dupont', 'company' => 'Dupont SARL'));
$t = time();
$headers[] = 'X-Data-Form-Email: '.$email;
$headers[] = 'X-Data-Form: '.$data;
$headers[] = 'X-Data-Form-Signature: t='.$t.'; s='.hash_hmac('sha256', $t."\n".$email."\n".$data, $key);
```
